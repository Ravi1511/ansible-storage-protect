
MULTI-SERVER IBM SPECTRUM PROTECT CONTROL NODE RUNBOOK
=====================================================

OBJECTIVE:
----------
- Single control node connecting to multiple Spectrum Protect servers
- Parallel backup of GPFS filesets
- Scalable, modular configuration
- Suitable for HSM and active binding

------------------------------------------------------------
1. ARCHITECTURE OVERVIEW
------------------------------------------------------------
Control Node (Client)
   |---- SP01 Server (fileset_2)
   |---- SP03 Server (fileset_3)
   |---- SP0N Server (fileset_n)

Each server is independent with its own:
- Node
- Policy
- Storage

------------------------------------------------------------
2. CLIENT CONFIGURATION (dsm.sys)
------------------------------------------------------------
Template:

SERVERNAME <SERVER_ALIAS>
  COMMmethod         TCPip
  TCPPort            <PORT>
  TCPServeraddress   <SERVER_IP_OR_HOSTNAME>
  NODename           <UNIQUE_NODE_NAME>
  PASSWORDACCESS     GENERATE
  ERRORLOGNAME       /var/log/tsm/dsmerror_<SERVER_ALIAS>.log
  SCHEDLOGNAME       /var/log/tsm/dsmsched_<SERVER_ALIAS>.log

Example:

SERVERNAME PETASCALE-SP01
  COMMmethod         TCPip
  TCPPort            1500
  TCPServeraddress   9.11.53.28
  NODename           hsm-client-03-sp01
  PASSWORDACCESS     GENERATE
  ERRORLOGNAME       /var/log/tsm/dsmerror_sp01.log
  SCHEDLOGNAME       /var/log/tsm/dsmsched_sp01.log

SERVERNAME PETASCALE-SP03
  COMMmethod         TCPip
  TCPPort            1500
  TCPServeraddress   9.11.53.254
  NODename           hsm-client-03-sp03
  PASSWORDACCESS     GENERATE
  ERRORLOGNAME       /var/log/tsm/dsmerror_sp03.log
  SCHEDLOGNAME       /var/log/tsm/dsmsched_sp03.log

------------------------------------------------------------
3. CLIENT OPTIONS FILE (dsm.opt)
------------------------------------------------------------
SERVERNAME PETASCALE-SP01

Note: Default server does not matter when using -servername

------------------------------------------------------------
4. CERTIFICATE MANAGEMENT
------------------------------------------------------------
For each server:

Extract certificate:

openssl s_client -connect <IP>:<PORT> -showcerts

Save certificate:

echo | openssl s_client -connect <IP>:<PORT> -showcerts 2>/dev/null \
  | sed -n '/BEGIN CERTIFICATE/,/END CERTIFICATE/p' > /tmp/<server>.arm

Add certificate:

/opt/tivoli/tsm/client/ba/bin/dsmcert \
  -add -server <SERVER_ALIAS> -file /tmp/<server>.arm

IMPORTANT:
- One client uses one cert DB
- Add ALL server certificates

------------------------------------------------------------
5. SERVER SIDE CONFIGURATION
------------------------------------------------------------
On each server:

register node <NODE_NAME> <PASSWORD> domain=STANDARD maxnummp=4

Example:

register node hsm-client-03-sp01 Pass123 domain=STANDARD
register node hsm-client-03-sp03 Pass123 domain=STANDARD

------------------------------------------------------------
6. POLICY SETUP (PER SERVER)
------------------------------------------------------------
Policies are independent per server:

Example:

define domain GPFS_DOMAIN
define policyset GPFS_DOMAIN STANDARD
define mgmtclass GPFS_DOMAIN STANDARD MC_DEFAULT
assign defmgmtclass GPFS_DOMAIN STANDARD MC_DEFAULT
activate policyset GPFS_DOMAIN STANDARD

------------------------------------------------------------
7. GPFS FILESET BACKUP DESIGN
------------------------------------------------------------
IMPORTANT:
- DOMAIN must be filesystem, not directory

Correct:
DOMAIN /gpfs_main

Use fileset path in backup command

------------------------------------------------------------
8. PARALLEL BACKUP COMMANDS
------------------------------------------------------------

Example:

dsmc incr /gpfs_main/fileset_2 -servername=PETASCALE-SP01 &
dsmc incr /gpfs_main/fileset_3 -servername=PETASCALE-SP03 &

------------------------------------------------------------
9. HSM DESIGN PRINCIPLES
------------------------------------------------------------
Each fileset must map to:
- Dedicated server
- Dedicated node

Example:
fileset_2 -> SP01 -> hsm-client-03-sp01
fileset_3 -> SP03 -> hsm-client-03-sp03

------------------------------------------------------------
10. ADD / REMOVE SERVER
------------------------------------------------------------
Add:
1. Add entry in dsm.sys
2. Register node
3. Add certificate
4. Run backup

Remove:
1. Remove config block
2. Stop jobs
3. Optional cert cleanup

------------------------------------------------------------
11. VALIDATION COMMANDS
------------------------------------------------------------

Test client:
dsmc q sess -servername=<SERVER>

Admin access:
dsmadmc -se=<SERVER>

Check nodes:
query node

Check certificates:
gsk8capicmd -cert -list -db dsmcert.kdb -stashed

------------------------------------------------------------
12. COMMON ISSUES & FIXES
------------------------------------------------------------

Certificate error:
-> Extract + dsmcert add

SSL error:
-> Port mismatch

Auth failure:
-> Reset password or re-register node

Parallel failure:
-> Password not stored, use GENERATE

------------------------------------------------------------
13. BEST PRACTICES
------------------------------------------------------------

- Unique node per server
- Separate log files
- Use PASSWORDACCESS GENERATE
- Store all certificates
- Use -servername for parallel jobs

------------------------------------------------------------
