I've successfully automated multi-server HSM client configuration with per-server GPFS filesets. The solution supports both multi-server and single-server modes with backward compatibility.

1. Updated Configuration Files:
hsm-client-03.yml
New multi-server structure:

sp_servers:
  - name: "PETASCALE-SP01"
    address: "9.11.53.28"
    port: "1500"
    node_name: "hsm-client-03-sp01"
    domain: "/gpfs_main/fileset_2"
  - name: "PETASCALE-SP03"
    address: "9.11.53.254"
    port: "1500"
    node_name: "hsm-client-03-sp03"
    domain: "/gpfs_main/fileset_3"

default_server: "PETASCALE-SP01"

Key features:

Each server has its own node name (required for registration)
Each server backs up different GPFS filesets/domains
Default server specified for dsm.opt
2. Updated Playbook Logic:
petascale_configure.yml
Automatic mode detection:

Detects if sp_servers is defined → Multi-server mode
Falls back to legacy variables → Single-server mode
Generated dsm.sys (Multi-Server):

SERVERNAME PETASCALE-SP01
  COMMMethod         TCPip
  TCPPort            1500
  TCPServeraddress   9.11.53.28
  NODename           hsm-client-03-sp01
  DOMAIN             /gpfs_main/fileset_2
  ...

SERVERNAME PETASCALE-SP03
  COMMMethod         TCPip
  TCPPort            1500
  TCPServeraddress   9.11.53.254
  NODename           hsm-client-03-sp03
  DOMAIN             /gpfs_main/fileset_3
  ...

Generated dsm.opt:

SERVERNAME PETASCALE-SP01

3. How It Works:
Backup Operations:
# Default server (PETASCALE-SP01) backs up /gpfs_main/fileset_2
dsmc incremental

# Explicitly use PETASCALE-SP03 to back up /gpfs_main/fileset_3
dsmc incremental -servername=PETASCALE-SP03

Each Server Configuration:
Separate node names: Required for SP Server node registration
Separate domains: Each server backs up different filesets
Independent authentication: Each node needs its own password
4. Server Registration Required:
On each SP Server, register the corresponding node:

On PETASCALE-SP01 (9.11.53.28):

dsmadmc -id=admin -password=yourpass
register node hsm-client-03-sp01 <password> domain=HSM_DOMAIN

On PETASCALE-SP03 (9.11.53.254):

dsmadmc -id=admin -password=yourpass
register node hsm-client-03-sp03 <password> domain=HSM_DOMAIN

5. Testing the Configuration:
# Run the playbook
ansible-playbook playbooks/petascale_configure.yml \
  -i playbooks/inventory/petascale.ini \
  --limit hsm-client-03

# Verify configuration files
cat /opt/tivoli/tsm/client/hsm/bin/dsm.sys
cat /opt/tivoli/tsm/client/hsm/bin/dsm.opt

# Test connectivity to both servers
dsmc query session -servername=PETASCALE-SP01
dsmc query session -servername=PETASCALE-SP03

6. Backward Compatibility:
The playbook still supports single-server configuration. Just uncomment the legacy variables in hsm-client-03.yml:

# Comment out sp_servers and use these instead:
sp_server_name: "PETASCALE-SP03"
sp_server_address: "9.11.53.254"
sp_server_port: "1500"
node_name: "hsm-client-03"
gpfs_filesystem: "/gpfs_main"
